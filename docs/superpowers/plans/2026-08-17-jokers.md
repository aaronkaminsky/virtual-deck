# Optional Jokers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a config-panel toggle that puts two jokers — one red, one black — into the deck, or takes them out, resetting the table in the process.

**Architecture:** The `Suit` and `Rank` string unions in `src/shared/types.ts` gain joker members, so jokers are ordinary `Card` objects everywhere in the system — masking, dealing, dragging, and undo need no changes. The PartyKit server owns a new `jokersEnabled` boolean; a new `SET_JOKERS_MODE` action flips it, resets the table through the same path as `RESET_TABLE`, and rebuilds the draw pile from scratch with `shuffle(buildDeck(enabled))`. The client gets two new art files, a joker-aware sort rule, and a toggle button in the existing config popover.

**Tech Stack:** TypeScript, React 19, PartyKit (Cloudflare Workers), Vitest (unit), Playwright (e2e), Base UI components, Tailwind.

**Spec:** [`docs/superpowers/specs/2026-08-17-jokers-design.md`](../specs/2026-08-17-jokers-design.md)

## Global Constraints

- **Branch:** all work happens on `worktree-feat+jokers-1039` in the worktree at `.claude/worktrees/feat+jokers-1039`. Never commit to `main`; never `git merge` into local `main`.
- **Every commit must pass the pre-commit hook**, which runs `npm test` (Vitest) and `npm run typecheck` (`tsc --noEmit`). A task that breaks typecheck cannot be split across commits — this is why Task 1 bundles the display-map updates.
- **Never use `--no-verify`.**
- **Exactly two jokers**, ids `JOKER-r` (red) and `JOKER-b` (black). No configurable count.
- **Art files:** `public/cards/jumbo/redJoker.png` and `public/cards/jumbo/blackJoker.png`, both 210×315 with an alpha channel, matching the existing 52 PNGs. (Source-deck naming, as with `spadeAce.png` — see the deviation note at the end of this plan.)
- **Copy strings, verbatim:**
  - Button label: `Jokers on` / `Jokers off`
  - Button aria-label: `Enable jokers` / `Disable jokers`
  - Helper text: `Changing this reshuffles and returns all cards.`
  - Dialog title: `Turn jokers on?` / `Turn jokers off?`
  - Dialog body: `This returns every card to the draw pile and clears undo history.`
  - Dialog confirm button: `Reshuffle`
- **No `takeSnapshot()`** in the new server handler — mode toggles are not undoable, matching `SET_CHIPS_MODE` and `SET_TOKENS_MODE`.
- **Jokers get no rule semantics.** They are ordinary cards with distinct art and a sort position.

export function buildDeck(includeJokers = false): Card[] {
  const deck: Card[] = SUITS.flatMap(suit =>

// PNG header: 8-byte signature, then the IHDR chunk whose width/height are
// big-endian uint32s at byte offsets 16 and 20.
function pngSize(path: string): { width: number; height: number } {

```ts
// Jokers have no place in SUIT_ORDER/RANK_ORDER (indexOf would return -1 and float
// them to the front), so they get an explicit rank: after every standard card,
// red before black.
function jokerOrder(card: Card): number {
  if (card.suit === 'joker-red') return 1;
  if (card.suit === 'joker-black') return 2;
  return 0;
}

export function sortCards(cards: Card[], mode: 'bySuit' | 'byRank'): Card[] {
  return [...cards].sort((a, b) => {
    const aJoker = jokerOrder(a);
    const bJoker = jokerOrder(b);
    if (aJoker || bJoker) return aJoker - bJoker;
    if (mode === 'bySuit') {
      const suitDiff = SUIT_ORDER.indexOf(a.suit) - SUIT_ORDER.indexOf(b.suit);
      if (suitDiff !== 0) return suitDiff;
      return RANK_ORDER.indexOf(a.rank) - RANK_ORDER.indexOf(b.rank);
    } else {
      // byRank: rank primary, suit secondary
      const rankDiff = RANK_ORDER.indexOf(a.rank) - RANK_ORDER.indexOf(b.rank);
      if (rankDiff !== 0) return rankDiff;
      return SUIT_ORDER.indexOf(a.suit) - SUIT_ORDER.indexOf(b.suit);
    }
  });
}
```
